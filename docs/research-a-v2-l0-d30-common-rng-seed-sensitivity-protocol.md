## 比較条件・評価
1. 保存済みstep413の更新前Bと更新後A→noneの4行動確率を、原本照合後にfloat32 CPU tensorに復元。Python 3.11、torch==2.5.1+cpu、1スレッド、`ATEN_CPU_CAPABILITY` 未設定を固定する。確率を結果から調整しない。
2. **事前固定seed集合：整数0〜4095の4096件。** 各seedについて2つの独立した `torch.Generator(device="cpu").manual_seed(seed)` を作り、同一初期状態からB確率とA確率で `torch.multinomial(probs,1,generator=...)` をそれぞれ**1回だけ**実行する。各seedの乱数状態が抽選前に一致することを確認。元のstep413直前の乱数状態を使うD29の既知結果は別枠の陽性対照とし、4096件の集計に混ぜない。
3. 4×4行動遷移件数、総不一致件数と率、`none→left` 件数、`left→none` 件数、行動ごとの変化を記録。確率分布の全変動距離 `0.5*sum(abs(pA-pB))` を併記する。ただし**全変動距離をこの特定の同一乱数結合の不一致率の上限と断定しない**。4096seedは固定の記述統計であり、全seed・実Motor・PPO学習への一般化はしない。
4. 全4096seedの抽選完了、状態一致、件数合計4096、原本D29照合成立、再実行の完全一致、数値有限を満たすとき `valid_seed_sensitivity_audit`。不一致が0件でも全件でも判定を変えない。環境不一致・原本不一致・抽選失敗・件数異常なら `invalid_seed_sensitivity_audit` として失敗ログを残し、結果に合わせてseedや確率を変えない。
5. **停止条件：4096seedの2抽選（計8192抽選）＋D29原本再生960抽選＋既知陽性対照のみ。** 追加seed・再学習・探索的条件追加なし。結果が小さい場合も途中停止しない。
