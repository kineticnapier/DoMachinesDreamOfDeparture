# MCCXVI — DMDOD 4K/2K制限ベンチマーク（研究設計）

## 対象と検証段階

- ユーザー提供の `MCCXVI - JinoBeats.zip` 内 `25 MCCXVI/level.adofai`
- 譜面 SHA-256: `bc4c05370075f7c6d59e713456b7ac0e0ee92b023cef1e48822ee341a5c32f65`
- 角度データ 1,836、Midspin 16、通常入力対象床 1,820（独立の予備計算）
- SetSpeed 135、Twirl 491、Hold 39
- 譜面・音源・実際の人間のキー入力記録は GitHub に収録しない

**現在の解析結果は静的必要条件であり、Motorによる全Hitや
本家ADOFAIの制限遵守を検証したものではない。** DMDODの公式
`compile_adofai` 結果が得られたら独立予備計算と照合する。

## 静的キー数の必要条件

入力イベントの時刻を `t_i` とし、同じキーの再使用に最低
`τ` 秒、許容キー数 `K` を仮定する。同時入力では同じ時刻に
必要なキーの数を加算する。

```text
required_keys(τ) = max_t # { i : t - τ < t_i <= t }
required_keys(τ) <= K    必要条件
```

これは時刻窓に基づく必要条件。実際のキーの復帰時間、押下位置、
速度、予約状態、Hold、区間境界で引き継ぐキー状態は計算に含めない。

2432 BPM、180度直線を4キー均等で処理する場合、

```text
60 / 2432 s = 24.67105263 ms / 打鍵
4 * 24.67105263 ms = 98.68421053 ms / 同一キー
```

**4K区間では固定100ms以上の再使用禁止は配置の時点で不可能。**
80msの必要条件が満たされても、Motorが押下・復帰できるとは
限らない。2K区間にも約98.684msの必要キー再使用間隔が現れる。

## 比較計画

| 対象 | 設定 | 研究上の意味 |
|---|---|---|
| A | 既存8キー自由Motor | 比較基準。4K遵守は主張しない |
| B | 4K/2K厳守・固定80ms | 静的に配置可能な条件のMotor実行 |
| C | 4K/2K厳守・固定100ms | 配置不能な場合は実行前に棄権 |
| D | 同120/150/180ms | 同上。失敗理由を記録 |
| E | 4K/2K厳守・Motor状態を使う選択 | 押下・予約・位置・速度を基に判断 |

4K許可キー集合の初期仮定は
`{left_1,left_2,right_1,right_2}`、2Kは
`{left_1,right_1}`。これは人間の実際の使用キーを特定した
ものではない。許可キー集合の変更は別の感度分析として記録する。

制約付きMotorは、**当初の希望キーだけでなく代替候補も
許可キー集合内に収める**。制限外への逃避を成功としない。

## Motorの状態を使う方式

意思決定時点で、次の現在情報を使用する。

- `pressed`: 物理キーが押されているか
- `reserved`: すでに別イベントへ予約されているか
- `position / velocity`: 押下・復帰中の位置および速度
- `forward-predicted keydown`: 現在時刻から前向き予測した到達時間
- `phase_limit`: イベントの床に対応する許可キー集合

未来の実測や人間の未知譜面ログを計画に渡さない。
安全な候補がない場合は棄権・不可能と記録し、勝手にキー制限を解除しない。

## 評価の報告項目

1. 静的配置の可否：必要キー数、違反した床・時刻
2. Motorの結果：Hit、Miss、TooEarly、Overload、完走の有無
3. 4K/2K制限遵守：実際の物理キーを照合し、違反0件を求める
4. 運指計画の再現：`local_replan` 件数と `pressed/reserved` の原因
5. 運動の実測：同じ物理キーの最短再打鍵間隔、予測誤差
6. 前提：OracleかHUD-onlyか、使用したモデルとSHA-256

最も厳しい成功条件を **全Hit・制限違反0・再計画0** とする。
全Hitでも救済再計画が起きた場合は、希望した運指の完全実行とは
評価しない。

## 手順

1. 元のユーザー提供ZIPをローカルに置く（GitHubにはアップロードしない）。
2. DMDOD内で公式時刻計算による事前解析を行う。
3. 予備計算とイベント数、床1420付近の2432BPM、2K/4Kの必要キー数を照合する。
4. 4K床1420〜1459、2K床1276〜1419から短区間のMotor試験を行う。
5. 境界の状態リセットを伴う短区間試験と、全譜面の連続走行を区別して記録する。
6. 制限非表示区間を独立設定として処理し、全譜面での許可軸を監査する。

```powershell
python scripts/mccxvi_4k_benchmark.py `
  --zip "MCCXVI - JinoBeats.zip" `
  --timing official `
  --out reports/mccxvi-preflight.json
```

予備実装の検証は `--timing approximate` だが、**公式のDMDOD時刻計算とは
一致を確認していない**ため、成果報告では混同しない。

## 検証の限界

- 装飾表示は実際のゲーム側のキー制限強制を証明しない。
- スクリーンショットから人間のすべてのキー入力を復元していない。
- この譜面で制約値を選んだ後の結果を未知譜面への一般化とは呼ばない。
- 元の8キーMotor、H2.1固定規則、学習済み重みはここでは変更しない。
