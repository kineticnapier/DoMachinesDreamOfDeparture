# 研究A v2-L0-D5 — R1先行処理がR2初回更新に与える影響（実行前固定）

**状態：実行前固定。正式研究002は未承認。** D4の結果を見た後に立てた、D5固有の事前計画。結果に応じて判定を変更しない。

## 問いと唯一の操作因子

D3はR1の4モデルをすべて再実行した後にR2 A0 seed0を開始し、元R2の学習前評価・初回PPO更新と不一致になった。D4はR2単独の初回8試行では元R2と完全一致した。

**唯一の操作因子は、同じPythonプロセスでR2の前にD3と同じ順序でR1の4モデルを実行したかどうか。**

- baseline: 新規Pythonプロセスで元R1/R2/D3の記録を読み込んだ後、R2 A0 seed0の初期評価＋8試行＋PPO1更新をD3のTraceR2計測で実行。
- preceded: 別の新規Pythonプロセスで同じ記録を読み込み、D3のTraceR1/Recorderと元train_modelを使いR1 A0 seed0→A0 seed1→A1 seed0→A1 seed1を各256試行（32更新）厳密再現した後、**同じプロセス内で**R2 A0 seed0の初期評価＋8試行＋PPO1更新を同じTraceR2計測で実行。
- R1の4モデルは新条件の学習ではなく、D3での先行処理状態を再現するための固定再実行。元R1の全32学習行・0/128/256評価・最終チェックポイントSHAが1つでも不一致なら停止し、R2を実行しない。
- R2は各条件8試行・1更新のみ。残りのR2モデル、追加seed、256試行のR2再学習を行わない。先行R1の途中にR2の試行を挟まない。

## 固定入力・環境・禁止事項

- 元R1 Actions `41309837474`（artifact `13084957586`）、元R2 Actions `41312136897`（artifact `13086306292`）、D3失敗 Actions `41369778494`（artifact `13109230783`）を読み取り専用で使用。
- 比較対象は元R2・D3保存済みのR2 A0 seed0の初期評価・最初の更新。D4の報告は背景とする。
- Python 3.11 / PyTorch 2.5.1+cpu / `PYTHONHASHSEED=0` / CPU単一スレッド / OMP・MKL各1。D3と同じ`l0.train_model`、`TraceR1`、`TraceR2`、`Recorder`、元PPOを使用。学習・Motor・報酬・観測・乱数種・判定・身体制約・PPO係数は変更しない。
- 元の重み、結果、事前登録、PR #37〜#47を上書き・変更しない。結果保存先はD5専用。教師運指、BC、重み移植、指固有報酬なし。
- R1再現が失敗した場合、続くR2の値を歴史的比較に使わない。新しいR2の勾配を元R2の歴史的勾配として採用しない。

## 計測と事前判定

1. それぞれの新規プロセスで初期R2重みSHA、初期評価の全行、8試行の観測・行動・報酬・物理KeyDown、PPO損失、更新後の重みを保存。D4の`first_batch(True)`を変更せず再利用する。
2. baselineとprecededを厳密比較し、最初の差のフィールド・値を記録。元R2とD3保存済みの初期評価・最初の更新とも比較。比較には許容誤差を設けない。
3. baselineが元R2の初期評価・更新1と完全一致し、precededがD3の初期評価・更新1と完全一致し、両条件が異なる場合は**先行R1処理による状態差がD3不一致を再現**と判定。ただし内部の数値原因・個々の処理の因果は未確定。
4. 両条件に差があるがD3を再現しない場合は**先行処理の影響候補のみ**、両条件が同じなら**この比較で先行R1処理の影響は確認されず**と判定。
5. baselineが元R2と一致しない、R1の厳密再現失敗、記録欠損、テスト失敗の場合は**診断不能／失敗**とし、好都合な値だけを採用しない。
6. Hit/Extraと物理KeyDown、対応不能・再使用も両条件で報告。A0/A1の元評価とA3ランダム対照は変更しない。運指獲得・人間同等性・単指物理限界を成功判定しない。
