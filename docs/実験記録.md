## Experiment 003 — v0.9 BC Training Acceleration

**状態:** 進行中

### 目的

v0.9 press-persistence 学習の意味論をできる限り維持したまま、round ごとの Behavioral Cloning (BC) コストを削減する。

### 条件

- Dataset: `data/DMDOD-v090-tuf`
- Hidden size: 128
- Chunk size: 192 steps
- Round: 48 rounds × 12 epochs
- Fixed-point skip により、収束後は多くの round で heavy epoch が 2 回だけ実行される
- CPU: Ryzen 5 5600G
- GPU: RTX 3060 12GB
- CPU と CUDA の浮動小数点 kernel は bit-identical ではないため、CUDA backend は近似一致を許容する

### 経過

1. BC chunk 内の frame-by-frame `GRUCell` Python loop を `forward_sequence()` + fused GRU 呼び出しへ置換した。
2. sequence 順序、chunk 境界、hidden-state detach、loss、gradient clipping、Adam step 回数は維持した。
3. CPU 実測の reverse BC は複数 round で約 88〜93 秒に安定した。
4. 旧 heavy epoch は約 223.5 秒であり、round 全体の heavy path は大幅に短縮した。ただしこれは BC 単体と完全に同一の計測値ではない。
5. reverse BC 93.15 秒の内訳を計測した。
   - forward: 25.18 s
   - loss: 2.85 s
   - backward: 60.94 s
   - optimizer: 2.64 s
   - other: 1.55 s
6. Python overhead は支配的でなく、次の主要ボトルネックは GRU/autograd backward と判断した。
7. reverse BC のみを CUDA に載せる backend を追加した。CPU trusted model は直接更新せず、CUDA copy が epoch 完走した場合のみ state を CPU へ戻す。CUDA 失敗時は CPU fallback 可能な構造とした。
8. 最初の環境は `torch 2.14.0+cpu` で `torch.cuda.is_available() == False` だったため CUDA 実機テストが skip された。CUDA wheel へ差し替え後、CUDA 実機比較テストは 3 passed となった。
9. CUDA 実機テスト中、cuDNN から GRU weight が contiguous でないという warning が出た。各 chunk での再packを避けるため、一時的な packed `nn.GRU` を使う実装へ変更した。checkpoint/state_dict の構造は変更しない。

### 結果

- Batched GRU CPU path: 有効。reverse BC は約 88〜93 秒で安定。
- CPU profile: reverse BC の約 65% が backward、約 27% が forward。
- CUDA backend: CPU/CUDA 近似一致テストは通過。
- Packed-GRU warning 対策後の本番速度: **未計測**。

### 観察

- Python loop を除去した後は `other` が約 1.55 秒まで減り、C++ 化だけでは大きな追加短縮は期待しにくい。
- forward BC は immutable expert prefix cache が hit すると約 1.8〜2.0 秒まで短縮される。
- reverse BC は round-local sequence が先頭に来るため、同じ fixed-prefix cache をそのまま適用できない。
- 難しい round では Guard が 35〜50 秒程度まで増えることがあり、BC 以外の第二ボトルネックになる。
- CUDA 本番速度は packed-GRU 対策後に再計測して追記する。
