# 研究A v2 — 混合テンポ・物理介入評価の予備検証 v0

**状態：実行前に固定する予備検証。正式実験002の登録・学習ではない。**

新しい評価案は [運指獲得の成功条件 v2 草案（PR #40）](https://github.com/kineticnapier/DoMachinesDreamOfDeparture/pull/40)
を踏まえる。旧A002-P/R1/S1の結果を変更せず、新しい学習は実施しない。

## 目的

- 低速→高速→低速の**未学習の混合テンポ**を、既存のMotorを変更せず採点できるか。
- A0単指・A1二指、A1左指/右指の物理的無効化の評価が一貫しているか。
- 旧の保存済み方策と未学習A3の基準値を計測し、新規学習の結果を早まって成功認定しない。
- 左右交代率や使用率が偏っていても合否を決めず、実際のHit/Extra、各区間の成績、介入による変化を記録する。

## 固定する評価環境

- 物理Motor：`MotorEnv(same_hand=True, control_dt_s=.010)`、物理1ms、
  `personal_blue_switch_v0_1`（**変更なし**）。
- 各エピソードは24個の目標時刻・三つの8打区間を持つ。
  全目標には**指の正解ラベルなし**。
- 条件は次の3種類の等間隔ブロック列（ms）：
  - C0: `[220]×8 + [120]×8 + [220]×8`
  - C1: `[210]×8 + [115]×8 + [230]×8`
  - C2: `[250]×8 + [125]×8 + [200]×8`
  `intervals[k]` は目標`k`に到着する直前の間隔。
  初回目標の間隔は観測に使うだけ。
  よって`target[0] = start`、
  `target[k] = target[k-1]+intervals[k]/1000`（`k>0`）。
- 開始時刻：`0.837, 1.071, 1.293`秒の3種類。計9ケース。
- 判定窓は元の`±20ms`、目標は時刻順に一対一で割当てる。
  各KeyDownには一致した目標の番号と物理キーを保存する。
  Extraは隣接の目標に近いだけでHit扱いしない。
- 得点は全体と区間`[0..7], [8..15], [16..23]`で別集計。
  **区間の境界で重複や入力消失を起こさない**。
- 観測は従来の8次元：次の未処理目標までの相対時間を
  **その目標に到達する間隔で正規化**した値、正規化した当該間隔、
  左右指の位置・速度・押下状態。絶対時刻、目標番号、
  区間ラベル・将来区間の名称は与えない。
- モデルの出力は既存の4種類の物理指令。
- A0：右指を物理的に無効化。A1：両指。
  A1に対し左指を無効化／右指を無効化した介入も計測する。
  **指のコマンドをマスクし、別の指へ自動割当てしない**。

## 評価のみ・学習は行わない

- 元のR0/R1比較で保存された**8モデル**：
  GitHub Actions [41300077879](https://github.com/kineticnapier/DoMachinesDreamOfDeparture/actions/runs/41300077879)、
  artifact `13080738533`。重みをSHA-256照合する。
- 各モデルの4種の評価：
  通常`argmax`、通常`sampled`（4反復）、
  A1の場合はさらに**左指無効化・右指無効化**を`argmax`でそれぞれ実行。
  介入は同一方策・同一目標列、Motorのみ変更する。
- A3未学習対照：全4行動の一様抽選、A0/A1各9ケース×4反復。
- 確率抽選の乱数シードを次式で固定：
  `250000 + 100*case_index + repetition`。
  この式はA0/A1、R0/R1、モデルシードで共通。
- 学習済み方策は決定論的`argmax`も評価するが、
  `sampled`の成績を後から都合よく採用して
  合格へ書き換えない。
- 完全な試行行・全モデル・失敗条件をJSONに残す。
  実行途中の成績を見てケース、反復数や合否を変更しない。

## この予備検証で主張しないこと

- **成功条件v2の達成や正式研究002の開始・完了ではない**。
- 上記の220ms / 120msを単指の物理的限界に基づく厳密な
  不可能／可能の境界として扱わない。
- 旧方策は固定テンポで学習している。混合テンポへの
  成績低下があってもその原因を運指だけに限定しない。
- `argmax`介入で性能低下が起きても、
  単指という身体一般の不可能性は証明できない。
- 未学習の行動が物理的に両指へ出ても、
  それ自体は運指の**学習成果ではない**。
- 旧学習済みチェックポイントを更新しない。
  研究Bや正式`docs/実験記録.md`は変更しない。

## 実装の検査

1. 24目標、増分の計算、変速境界8/16での時刻差。
2. 全ての物理KeyDownで`hits+extras==physical_downs`、
   `hits+misses==24`（終了後）。
3. 指の無効化時の物理KeyDown側が0になる。
4. 全ケースで区間ごとの目標・命中・Miss数が全体に一致する。
5. 同一方策・同一ケース・同一抽選シードで完全再現。
6. R0/R1の元チェックポイントSHA-256を確認し、
   モデルや身体の変更を禁止。
7. 既存実験のコードを書き換えず、別環境で検証する。
