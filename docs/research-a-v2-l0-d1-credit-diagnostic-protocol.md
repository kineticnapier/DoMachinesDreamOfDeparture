# 研究A v2-L0-D1 — PPOの行動確率・物理打鍵遅延の事後診断（実行前固定）

**状態：予備実験の事後診断用条件。正式002の事前登録ではない。学習禁止。**

対象：実験L0 [Actions #41309837474](https://github.com/kineticnapier/DoMachinesDreamOfDeparture/actions/runs/41309837474)の**元の4最終モデルと全履歴**。
保存済みの学習記録、0回時点の再構築可能な未学習モデル、256回時点の最終モデルを使う。
元の身体モデル・報酬・学習コード・重み・合否基準は**変更しない**。

## 具体的に調べること

1. 学習0/128/256回の**元の保存済み評価ログ**から、各A0/A1×seed0/1の
   sampled/argmaxのHit・Extra・行動選択割合・平均方策Entropy・平均評価報酬を整理する。
   中間128回の重みは保存していないため、**方策そのものは再構築しない**。
2. 学習0回時点は`torch.manual_seed(seed); ActorCritic()`で重みを作り、
   学習256回は元の重みをSHA-256照合して読み込む。
   各時点で9ケースargmax+36ケースsampledを原評価と同じ乱数で実行。
   **元ログの各45行**のHit、Extra、KeyDown数、キー列、行動選択数、物理KeyDown記録を
   原データと完全照合する。1件でも不一致なら診断の妥当性なし。
3. 押下指令が`非正→正`へ遷移した時刻と、その指の実KeyDownとの遅延を集計。
   指令から実際のKeyDownまでの時間は、身体の遅れを見る**記述統計**で、
   PPOの勾配に配分された信用を直接計測するものではない。
4. 次の未処理目標までの残り時間を4区間
   （100ms超前、20〜100ms前、±20ms、20ms超後）に分け、
   選択された4行動`none,right,left,both`の割合・Softmax平均・Entropyを記録する。
5. 実KeyDownに対して、Hit/Extra、近傍目標との時刻誤差、
   キー別件数、対応する押下指令開始からの遅延を**全件**記録する。
6. PPOが実際にどの行動へ勾配を割り振ったかは、**当時の更新前状態・行動別優位度の
   生の記録がない**ので、この事後診断から断定しない。
   元の32更新分の`entropy/loss/train_reward/train_hit_rate`は別欄で再整理する。

## 固定した再生条件

- L0のA0/A1、seed=0/1の4モデル全件。元の学習実行ソースSHA
  `fa456d0e07e90fb740d969715f593f81c1ee48c3`。
- 0回モデルの再構築＋256回の原最終モデルの2時点を再生。
  128回は**保存ログのみ**で集計。
- 間隔210/240/250ms、開始0.835/1.075/1.290s。
  argmax9試行、sampled36試行を各時点・各モデルに実施。
  sampled乱数は元の`320000+100*case_index+repetition`、4反復。
- R1報酬（不命中の正の近傍報酬なし）、同じMotor・同じ8次元観測、
  同じ4行動と判定窓。絶対時刻や指の正解は追加しない。
- どのモデルも再学習・追学習・重み選択をしない。
- 主要な報告は全4モデル、0/128/256の推移と
  256時点の学習された方策の最終観測結果。
- **成功条件の変更なし**（旧L0はHit90%以上、Extra/目標5%以下で未達）。
- 差の統計的有意性、単指の物理的な不可能性や運指の自力獲得は主張しない。
- 実行が途中で止まった場合も正常完了と偽らず`pipefail`でエラーを伝播する。
