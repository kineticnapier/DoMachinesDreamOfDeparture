# 研究A v2-L0-D4 — R2の再現不一致を最初のPPO更新で切り分ける（実行前固定）

**事前登録状態：計測前固定。正式研究002は未承認。** 本書のコミット後に診断を実行し、観測結果に合わせて判定条件を変更しない。

## 背景と問い

D3の元学習再現ではR1の4モデルが完全一致したが、R2 A0 seed0の全256試行は元R2と不一致だった。元R2 Actions `41312136897`、D3 Actions `41369778494`（後続の`41370150901`も失敗）を保存済みとする。

**問い：R2 A0 seed0の最初の8試行／最初のPPO更新で、元R2の記録、元の環境による再実行、D3の計測付き再実行のどこから差が生じるか。** 今回は原因の特定に必要な最小の診断だけを行い、全256試行の再学習はしない。

## 入力と変更禁止

- 元R2のActions `41312136897`、artifact `13086306292` の `full-comparison.json` とチェックポイントは読み取り専用。
- D3のActions `41369778494`、artifact `13109230783` の `full-diagnostic.json` は読み取り専用。
- 元R2の実行ソース `773ad68c4cb28f4c2ab8aaf2aeaffecdfd8ec95e` とD3のソース `5d799475a8fdd471f95ae96c9e0f9cc730cbbd98` の学習・報酬・Motor関連ファイルの内容SHAを照合する。
- 比較対象は**R2 A0 seed0のみ**。A0/A1の学習条件、PPO、ActorCritic、報酬、物理Motor、8観測、4行動、学習間隔200/260ms、開始0.78〜1.12s、評価0/128/256、抽選種を変更しない。
- Python 3.11 / PyTorch 2.5.1+cpu / CPU単一スレッド、`PYTHONHASHSEED=0`。
- 学習済みR1/R2/A3の評価指標や重みは変更せず、教師運指・重み移植・追加報酬を導入しない。

## 手順と比較対象

1. 元R2の32更新記録とD3再実行の32更新記録を**計算せずに**比較する。初期評価、更新番号ごとの`periods_ms`、`starts_s`、Hit、Extra、平均報酬、PPO loss・entropy・value loss・policy loss、128/256評価を順に比較し、最初の不一致位置・値・差を保存する。両ログの順序と長さを検査する。
2. 元の`PenalizedLoggedLowSpeedEnv`を使い、R2 A0 seed0を最初の**8試行＋1回のPPO更新だけ**再実行する（baseline）。元の`train_episode`と`update_ppo`を直接使用する。
3. 同じ初期重みと乱数種からD3の`TraceR2`・`Recorder`を使い、**8試行＋1回のPPO更新だけ**再実行する（instrumented）。D3の既存計測実装を変更しない。
4. 両者の初期評価、各試行の観測・行動・旧対数確率・旧価値・割引報酬・得点・間隔・開始時刻、PPO損失、更新後の全モデル重みを比較する。計測側の実際の物理KeyDown数・Hit・Extraも保存する。
5. baseline/instrumentedそれぞれの最初の更新記録を元R2の1行目と照合する。D3の保存済み1行目との一致も確認する。

## 事前固定した判定

- baselineとinstrumentedが異なるなら、**計測の副作用候補**とし、最初の相違フィールドを報告する（因果確定ではない）。
- baselineとinstrumentedが一致し、両方とも元R2の初回更新と異なるなら、**元実行と現在の再実行の条件差候補**とする。ソース・依存関係・乱数・数値環境を引き続き調査する。
- baselineとinstrumentedと元R2の初回更新が一致するなら、**初回更新では不一致を再現できない**と報告し、保存済み32更新の比較から次の調査範囲を示す。
- 初期評価や入力に不整合がある場合、**再現失敗／診断不能**とし、都合のよい数値だけを採用しない。
- どの結果でも、D3のR2の勾配を元学習の歴史的な勾配と呼ばない。全32更新・全評価・最終重みSHAが完全一致するまでD3の全体成功とはしない。

- 元ログ／D3ログが欠けている、SHAや型・記録件数が不正、比較コードのテストが失敗した場合は診断を中止し、失敗を記録する。
