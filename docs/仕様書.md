# v0.1 仕様

## 1. 目的

人間と同等の知覚・身体的制約を与えられた学習機械が、ADOFAI において人間とは異なる有効な運指を獲得できるかを調べる。

「最強の Bot」を作ることは目的ではない。身体能力を可能な限り固定し、学習・予測・運指の違いを調べる。

## 2. 構成

```text
ADOFAI Environment
        |
      知覚
        v
      Agent
        |
    運動指令
        v
    神経遅延
        |
        v
     手モデル
        |
        v
 キーボードモデル
        |
        v
      Input
```

Agent、知覚、手モデル、キーボードモデル、環境、記録・評価器は独立して交換可能にする。

## 3. 禁止する情報・操作

本番条件では、エージェントは以下を利用できない。

- `.adofai` から正解入力時刻を直接取得する
- ゲーム内部の beat や判定予定時刻を取得する
- Otto / Autoplay の情報を利用する
- ゲーム速度・判定幅を変更する
- キー入力を直接発火する

エージェントが出力できるのは身体への運動指令のみとする。

## 4. 時間

身体シミュレーションは固定刻みとし、初期値を

```text
Δt = 1 ms (1000 Hz)
```

とする。方策の更新周期はこれと分離し、初期値を 100 Hz とする。

## 5. 手モデル v0.1

最初は2本指のみを扱う。

```text
Left
Right
```

各指 `i` の状態を

```text
S_i = (x_i, v_i, a_i, f_i)
```

とする。

- `x_i`: 指の位置
- `v_i`: 指の速度
- `a_i`: 筋活動
- `f_i`: 疲労

エージェントの行動は

```text
u_i ∈ [-1, 1]
```

であり、`+1` は最大限押す方向、`0` は能動的な力なし、`-1` は最大限戻す方向を表す。

## 6. 筋肉応答

運動指令を即座に力へ変換しない。

```text
τ_a da_i/dt = u_i - a_i
```

利用可能な力を

```text
F_i = F_max (1 - f_i) a_i
```

とし、簡略化した指の運動を

```text
m_i d²x_i/dt² = F_i - c_i dx_i/dt - k_i(x_i - x_0,i)
```

とする。各式は人体の確定モデルではなく、実測結果に合わせて交換・調整する対象である。

## 7. キーボード

キーには作動点と復帰点を持たせる。初期値の例：

```text
travel      = 4.0 mm
actuation   = 2.0 mm
reset       = 1.8 mm
```

下降中に作動点を通過したときのみ `KEY_DOWN` が成立し、復帰点まで戻らなければ次の入力は成立しない。

## 8. 疲労

v0.1 の暫定モデル：

```text
df_i/dt = α |a_i| - β f_i
0 <= f_i <= 1
```

疲労によって利用可能な最大筋力を低下させる。ただし疲労式は将来の実測によって変更する。

## 9. 指同士の干渉

2本の指を完全独立とはしない。v0.1 では簡略化した干渉を導入する。

```text
F'_i = F_i (1 - γ |a_j|)
```

将来10指へ拡張する場合は、指ごとの干渉を行列などで表現できる設計にする。

## 10. 知覚

### Mode A: Symbolic

開発・身体モデル検証用。現在角度、次の床の相対情報、回転速度などの抽象化した状態を与える。正解入力時刻そのものは与えない。

### Mode B: Visual

本番用。ゲーム画面から知覚する。フレーム更新周期と知覚遅延を持たせる。

```text
observation at t = I(t - τ_visual)
```

未来を内部で予測することは禁止しない。人間も先読みと運動準備を行うためである。

## 11. 強化学習

初期実装では連続行動を扱える手法を使用する。候補として PPO を想定するが、方式は固定しない。

行動：

```text
a_t = (u_left, u_right)
```

報酬の基本形：

```text
R = R_hit - λ_t |timing_error| - λ_e E - R_miss
```

消費量の簡略値：

```text
E = Σ a_i²
```

報酬によって特定の運指を直接教えてはならない。

## 12. 学習段階

```text
Stage 0  単発入力
Stage 1  一定BPM
Stage 2  BPM上昇
Stage 3  2本指交互が有利になる速度
Stage 4  BPM変化
Stage 5  簡単なADOFAIパターン
Stage 6  高難度
Stage 7  U帯の最前線
```

Stage 3 が v0.1 の主要実験となる。交互押しを明示的に教えず、エージェントが自力で獲得するかを見る。

## 13. 人間モデルの校正

人体パラメータを「それらしい値」で決めるだけではなく、人間の測定結果に合わせる。

候補となる測定：

- 単指連打
- 2指交互
- 同時押し
- 徐々に速度を上げる試験
- 長時間連打
- 不規則タイミング

人間の測定結果を `H_j`、モデルの結果を `M_j(θ)` として、概念的には

```text
θ* = argmin_θ Σ_j w_j D(M_j(θ), H_j)
```

とする。

## 14. 未知試験

校正に使った課題だけで人間に似ていても十分ではない。一部の運指・速度変化を校正に使わず残し、未知条件でも人間と似た性能曲線を示すか検証する。

```text
校正: 単指、LR交互、持続連打
未知: LLR、LRR、LLRR、不規則BPM、短いburst
```

## 15. 記録

最低限、以下を各試行で保存する。

```text
timestamp
observation
policy output
finger position
finger velocity
muscle activation
fatigue
key state
target timing
actual timing
timing error
judgement
reward
```

研究用の正解時刻は評価・解析器が保持してよいが、エージェントの観測へ流してはならない。

## 16. v0.1 で実装しないもの

- 10指
- 手首・腕
- 詳細な腱・骨格モデル
- 3D人体
- 個々の実在筋肉の再現
- 本番用視覚入力
- 音声知覚
- 実ADOFAIへの直接接続

まずは

```text
2指物理モデル
+ 簡易リズム環境
+ 強化学習エージェント
```

とする。

## 17. v0.1 成功条件

単指では身体モデル上物理的に突破できない速度の入力列を用意する。運指に関する説明・報酬を与えず、エージェントが2本の指を利用した周期運動またはそれ以上に有効な戦略を獲得して突破すること。

```text
単指: 突破不能
学習した戦略: 突破
```

これを v0.1 の最初の到達点とする。
