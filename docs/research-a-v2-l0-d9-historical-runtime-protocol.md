# 研究A v2-L0-D9 — 保存済み実行環境の証拠監査（実行前固定）

**状態：解析実装・CI実行前の固定計画。正式研究002は未承認。** D8までの失敗を受けた事後診断であり、盲検実験ではない。

## 問いと対象

D3は元R1の学習更新を再現したが元R2の再現に失敗し、D5/D7は元R1の数値再現に失敗した。D8では同じ初期重みでもCPU命令経路の変更でEntropyが変わった。今回は**元の実行でどの計算環境が実際に記録されていたか**だけを、保存済みGitHub Actionsジョブログと診断成果物から確認する。CPUの個体差・演算経路の因果効果を新たに実験しない。

固定する元ジョブ：R1 run 41309837474 / job 124857703147、D3 run 41369778494 / job 125037538287、D5 run 41380105087 / job 125068823089、D7 run 41391082538 / job 125102397739、D8 run 41397065687 / job 125120568955。D7 artifact 13116998596 の result.json とD8 artifact 13119278298 の native.json を参照する。元R2の実行条件については、元R2のジョブを追加取得できた場合のみ補助的に記録し、上記5ジョブの判定には混ぜない。

## 監査項目と事前判定

1. 各ジョブログから runner version、OS image、image release、Python実行場所（3.11系）、pipで実際に導入されたPyTorch、PYTHONHASHSEED/OMP_NUM_THREADS/MKL_NUM_THREADS を抽出し、元ログへのジョブURLを保存する。
2. D7/D8の既存JSONからCPUモデル、CPU機能、PyTorch版、thread数、MKLDNN状態を取得し、ログ由来の版・設定と矛盾がないか確認する。ログにないCPUモデル・ATen機能を**推測して補わない**。R1/D3/D5についてCPUの実機情報がない場合はunknownとする。
3. R1/D3とD7/D8の学習前Entropy（R1/D3 1.3561848871858129、D7/D8 native 1.3561848983669778）とD8 default 1.356184897858743を過去の確定記録として並べる。過去の学習・評価は再実行しない。
4. 5ジョブのログが揃わない、Python/Torch情報が読み取れない、JSONに矛盾がある場合は invalid_archive_audit。主要な表示環境が一致しても元R1/D3/D5のCPU個体・ATen経路が未記録なら **historical_cpu_unresolved**。完全に実行経路が確認できる場合に限り runtime_evidence_complete。**同じOSイメージを同じCPUとみなさない。**
5. 比較結果は既知の数値差を説明する証拠があるかを記録する。環境が似ているだけでCPU起因と断定しない。Hit/Extra・物理KeyDown・A0/A1/A3の既存評価は読み取り専用とし、新規打鍵0、学習0試行、PPO更新0回。

ログ取得失敗やパーサーの検査失敗は結果を成功扱いせず、取得済み証拠と失敗理由を保存する。すべての根拠・否定的結果・未記録項目をJSONと文書に残す。事前判定条件を後から変更しない。既存PR #34/#37〜#51、元重み、身体、報酬、学習器を変更しない。新しいDraft PRに隔離し、自動マージとDraft解除を永久に禁止する。
