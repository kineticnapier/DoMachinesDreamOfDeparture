# 研究A v2-L0-R2 — 余分な打鍵への一律減点比較（実行前固定）

**状態：予備比較実験の事前固定。正式研究002の事前登録ではない。**
この文書はR2学習を始める**前**にコミットする。旧L0-R1は
学習失敗の結果を含めて変更しない。

## 問いと単一変更点

研究A v2-L0の学習では、Hitと同時にExtraが増えた。
R1では判定窓の外側20〜80ms付近の余分なKeyDownが、原則として
即時の加点も減点も0である。ここだけを変えて、R2では
**Hitしなかった物理的KeyDownすべてに、一律の直接報酬 -0.05**
を与える。遠いExtraはR1ですでに-0.05なので変更しない。

- **R1（対照）**：元L0の`LoggedLowSpeedEnv`、報酬を一切変更しない。
- **R2**：上記R1から、20ms < |次の未処理目標との差| <= 80ms の
  非Hit KeyDownに**追加の-0.05**。同じHit(+1.0−精度控除)、Miss(-0.10)、
  期限切れ、目標の割り当て、外側80ms超のExtra(-0.05)は維持。
- 「正解の指」「左右交代」「得意な指」には報酬を与えない。
- この1点以外のMotor、PPO、行動、観測、端点時刻、
  Hit/Extra判定と学習の停止位置は変えない。

固定操作列をR1/R2の環境に流し、**物理的なKeyDown列、Hit、
Miss、Extra、状態、終了が完全一致**することをテストする。
同じ操作列においてR2とR1の報酬差が
`-0.05×（対象の近傍Extra数）`であることをテストする。

元のL0と同じ：

- A0（右指を物理的に無効化）、A1（両指使用可能）

- 学習は200ms/260ms、各16打、開始0.78〜1.12秒
- A0/A1各seed0/1、256エピソード/モデル、計R2新規4モデル
- PPO 8エピソードごとに2回更新、lr0.0005、gamma0.99、
  clip0.2、entropy係数0.01、value係数0.5
- 評価は未使用の210/240/250ms×開始0.835/1.075/1.290秒
- 評価時点は0/128/256エピソード

- CPU単一スレッド、Python3.11、PyTorch2.5.1+cpu
- 指の教師、BC、教師チェックポイント、指依存の加点・減点なし
- 追加学習の停止回数・シード・評価方法は結果を見て変更しない

## 指標と判定

**主指標**：各シードの未学習評価（sampled）で、
Hit率とExtra KeyDown/目標数を**両方報告**する。
評価0→128→256時点の推移をR1/R2で併記。
A0/A1両シード、悪化した条件も含め全件報告。

参考成功目安は旧L0を変更せず
**Hit率90%以上かつExtra/目標5%以下、全4モデルで達成**。
左右使用率と交代率は参考値でしかなく成功判定に使わない。

R2がR1より少しよくても、2シードのみなので
「一般的に改善」「運指の自力獲得」などとは主張しない。
R2が改善しなければ、原因が「近傍Extraの無罰」だけだった仮説を
この学習予算では支持しない。
元L0の失敗・正式002未承認は維持。

**注意**：同じ乱数種でもR1/R2で学習後の方策が違えば、
実際の行動列は一致しない。それは意図した比較の一部であり、
身体条件を変えたことにはならない。
