## 2. 何を計算したか

実際に物理KeyDownが生じた指について、直前の
**非正→正の押下指令開始時刻**を追跡した。
この指令を出した10ms区間における
`G_t = r_t + 0.99 G_{t+1}`、
`A_t = G_t - V(s_t)`を計算した。
全36評価試行の行動に対して平均0・標準偏差1に正規化している。

この数値は**最終方策の評価時に後から計算した優位度近似**である。
元の学習時の8試行ずつのPPO勾配ではない。
物理KeyDownとの時間的対応は**行動の真の因果的寄与を証明しない**。
同一試行内の他のHitの報酬も`G_t`に入るため、
Extraに対応した指令の優位度が正になることもある。

## 4. 否定的結果と解釈

**実測されたこと**

1. R1/R2の8モデル・全288評価試行を、保存結果と完全一致で再現した。
2. Hitの押下開始は優位度近似が正、Extraは平均では負。
   ただしExtraの**約4分の1〜3分の1が正**で、
   R2でもこの割合が一様に減少しない。
3. Hitに対応した指令は、物理KeyDownより約30〜35ms早い。
4. A1両シードはR1/R2とも安定学習に未達。
   低速打鍵の成否基準（Hit90%以上、Extra/目標5%以下）を
   全8モデルが満たさず、完全Hit試行も0。

**実測できていないこと**

- 元の32回のPPO更新で各指令が受けた**歴史的な勾配**。
- あるExtra指令の優位度が正だったことが、
  その指令をPPOが強化した**直接の原因**であるという証明。
- すべての学習失敗が優位度の符号の誤りに起因するという因果関係。
- 人間の身体と同等であること、単指では物理的に不可能なこと、
  教師なしの運指獲得が成立したこと。

**結論**：報酬を減点するだけでは、成功した打鍵と
余分な打鍵を安定して選び分ける学習には至らなかった。
事後の優位度近似はHitとExtraを平均では区別するが、
Extraに対して正の値が残る。
これが学習時の更新を妨げているかは未証明。

次の独立した実験候補は、**学習中の更新直前に8試行分の
行動・報酬・価値・優位度を直接記録**して、
実際の更新方向を測ること。
ただしその実験は**別の事前固定条件**を必要とし、
このD2の結果を遡って変更しない。
